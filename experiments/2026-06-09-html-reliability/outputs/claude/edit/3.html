Feature-flag system

Add a feature-flag system: schema, evaluation engine, admin UI.

Success criteria

Flags evaluate in under a millisecond at p99 with no added network hop.

Scope

Schema, evaluation engine, admin UI. No A/B-test stats, no mobile SDKs.

Constraints

No new external SaaS dependencies. Three engineers, six weeks.

Assumptions

Phase 1: Flag schema and storage

Define the flag model and decide where flags live.

Phase goal

A migrated feature_flags table with a typed accessor library.

Alternatives considered

Config-file-in-repo was considered; rejected because support needs runtime kill switches without a deploy.

Recommendations

Use a 30-second poll with push-assisted invalidation

Poll the flags table every 30 seconds as the baseline, and layer a LISTEN/NOTIFY push channel on top so kill switches propagate in under a second without making the push path load-bearing.

Open questions

What cache invalidation latency is acceptable for kill switches?
